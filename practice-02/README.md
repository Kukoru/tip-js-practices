## 4. Модель данных и функции

**Модель задачи:** `{ id, title, completed, priority }`.

**Правила валидации:**
- `id` — положительное безопасное целое (`Number.isSafeInteger`).
- `title` — строка, после `trim()` от 1 до 100 символов.
- `completed` — boolean, при создании всегда `false`.
- `priority` — `"low" | "medium" | "high"`, по умолчанию `"medium"`.

**Назначение файлов:**
- `data.js` — исходные массивы (`demoTasks`, `variantTasks`).
- `task-service.js` — девять прикладных функций (без вывода в консоль).
- `main.js` — демонстрационный сценарий и вывод.
- `checks.js` — готовые проверки через `node:assert/strict`.

**Почему id не равен индексу:** id идентифицирует запись и не меняется при удалении соседних элементов. Индекс показывает текущее место в массиве.

**Почему `getTaskStats` возвращает число, а не строку с процентом:** число можно использовать в дальнейших расчётах; округление (`toFixed(1)`) выполняется только при выводе.

**Какие объекты копируются при изменении задачи:** создаётся новый массив (`[...]`, `map`, `filter`) и новый объект только для изменяемой записи (`{...task, поле: значение}`). Остальные записи переиспользуются.

## 8. Расширение

**Выбранный вариант:** Вариант А — поиск задач по части названия.

**Контракт функции `searchTasks(tasks, query)`:**
- `tasks` — корректный массив задач модели.
- `query` — строка (при не-строке приводится к строке через `String`).
- Возвращает новый массив задач, в названии которых есть подстрока `query` (без учёта регистра).
- Пустой или пробельный запрос возвращает новый массив всех задач.
- Порядок записей сохраняется, исходный массив не изменяется.

## 9. Вывод

По сравнению с ПР1 работа перешла от отдельных переменных к массиву объектов и функциям. Возвращаемые значения используются для передачи результата между функциями и сценарием: `main.js` получает объект `{ ok, tasks }` и решает, обновлять ли состояние.
