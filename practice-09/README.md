## Цель и результат

**Цель:** Освоить создание HTTP API на Express, реализовать маршруты чтения, фильтрацию и обработку ошибок.

**Результат:** Реализован сервер, который возвращает health-статус, категории, список задач (с фильтрами по статусу, приоритету, категории и поиску) и отдельную задачу. Ошибки возвращаются в едином формате. Методы GET, HEAD, OPTIONS работают. Операции записи (POST, PATCH, DELETE) пока не реализованы и возвращают 405.

## Реализация

- **`validation.js`**: `parsePositiveId` проверяет строку регулярным выражением `/^[1-9]\d*$/` и `Number.isSafeInteger`. `parseFilters` проверяет имена параметров, запрещает дубликаты, преобразует `completed` в boolean (только `"true"`/`"false"`), проверяет `priority`, `categoryId` и обрезает `q`.
- **`task-service.js`**: `selectTasks` фильтрует по всем полям через И, поиск по `title` без учёта регистра. `findTask` ищет по `id`.
- **`store.js`**: хранит копии данных для экземпляра приложения.
- **`routes.js`**: GET-маршруты и `router.all` для 405.
- **`app.js`**: подключает middleware (CORS, OPTIONS, Router, 404, errorHandler).
- **`server.js`**: запускает порт.

**Нормализация false:** используется явное сравнение `raw === 'true'`/`'false'`, потому что `Boolean('false')` равно `true`.

**Контроль дубликатов query:** проверка `searchParams.getAll(name).length > 1`.

**Порядок middleware:** OPTIONS → Router (GET) → router.all (405) → 404 → errorHandler.

Успешный ответ: `{ "data": ... }` с `meta.total` для списков.

## Контрольные вопросы

1. **Чем JavaScript в Node.js отличается от JavaScript в браузере?** В Node.js нет DOM, `window`, `localStorage`; есть доступ к файловой системе и сети.
2. **Что определяет выбор маршрута?** Метод HTTP и путь.
3. **Чем `req.params` отличается от query-параметров?** `req.params` — часть пути (`/tasks/:id`), query — после `?`.
4. **Почему `'false'` требует явного преобразования?** `Boolean('false')` равно `true`.
5. **Зачем проверять весь id и `Number.isSafeInteger`?** Чтобы `4abc` не превратилось в 4, а число было безопасным.
6. **Почему пустая выборка — 200, а отсутствующая задача — 404?** Пустая выборка — корректный результат фильтрации; отсутствующая задача — отсутствие ресурса.
7. **В чём различие `TASK_NOT_FOUND` и `ROUTE_NOT_FOUND`?** Первое — задача не найдена, второе — маршрут не существует.
8. **Чем 405 отличается от 404 и зачем нужен `Allow`?** 405 — метод не поддерживается, `Allow` сообщает допустимые методы.
9. **Что означает `meta.total` при активных фильтрах?** Размер полученной выборки.
10. **Как порядок middleware влияет на результат?** Если 404 раньше роутера, он перехватит все запросы.
11. **Почему обработчик ошибок имеет четыре параметра?** Express распознаёт его как обработчик ошибок.
12. **Зачем фабрика приложения отделена от открытия порта?** Для тестирования без запуска сервера.
13. **Какие данные допустимо отправлять клиенту при внутренней ошибке?** Только код и общее сообщение, без стека.
14. **Почему CORS не является авторизацией?** CORS — правило браузера, а не проверка прав.
15. **Какие изменения потребуются в ПР10?** Добавить POST, PATCH, DELETE и проверку тела запроса.
